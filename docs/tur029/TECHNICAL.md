# TUR029 technical — real disposable PostgreSQL 16 owner/rights/runtime boundary
Stacked on TUR028 exact final SHA ed2e61d653e36cf1c61fd3e840c8c0dd758d4185 (Draft PR #32).
A dedicated PG16 job exercises four independent password-authenticated LOGIN roles: schema owner, rights writer, runtime reader, outsider. Tests prove runtime cannot UPDATE, outsider cannot SELECT/CREATE before grant, CREATE drift permits outsider object creation, revocation does not erase the created object, and owner can directly bypass rights-admin policy. Real COMMIT followed by deliberately discarded ACK is reconciled via a new connection; real ROLLBACK is verified after reconnect. This is a **known post-COMMIT ACK loss simulation**, NOT actual TCP interruption during COMMIT or unknown server outcome. Existing TUR021 PG16 SECURITY DEFINER and durable fence suites are rerun. No production logic or IAM implementation was changed.
