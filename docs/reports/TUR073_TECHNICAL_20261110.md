No superuser, role membership or `pg_signal_backend` is granted to this canceler. The SQL must terminate with SQLSTATE `57014`, original CMS handler return fail-closed 503, fictional R2 body and independent guardian SQL skip; concurrently active sibling query must complete normally. Media backend connection remains usable after error because the canceled SELECT runs outside a transaction. Media owner/canceler cannot mutate independently owned guardian, guardian reader cannot cancel media backend. This tests an **owned dedicated connection** and a fixed backend PID. It is NOT an approved production canceler: a same-role canceler may be able to cancel *any* process of that role, connection pool reuse/PID identity rotation is not solved, and narrow per-request authority requires new session-bound proofs. No production privileged cancellation path is wired.
