# TUR073 Security — same-role query cancellation does not equal request-scoped IAM

The proposed cancellation uses **two genuinely independent PostgreSQL16 password sessions of the SAME restricted media-reader login role**: reader executes an actual `pg_sleep` query and canceler issues `pg_cancel_backend(pid)` after physical Node HTTP socket close. PostgreSQL natively permits cancellation of same-role queries without a global `pg_signal_backend` grant, but that **does not prove** the canceler is restricted to one HTTP request. Any production design must verify session ownership, prevent backend-PID reuse, avoid pooled-connection reassignment, and protect canceler credentials. The CI-only fixture dedicates its client/backend to the aborted request and explicitly verifies that a separate sibling query of the same role was not canceled; a malicious or buggy canceler could still target a sibling with a different PID. Treat shared same-role cancel credentials as authority to disrupt all queries under that role. No broad pg_signal_backend, superuser or arbitrary PID from HTTP parameters is introduced.

`apps/web/app/media/cms/[id]/route.ts` now combines `NextRequest.signal` + a 6-second deadline and rejects already canceled upstream results. Tests prove signal composition in the actual route function, **not** whether real Next production HTTP socket disconnect fires `NextRequest.signal`; separate physical Next transport CI is required. The Cloudflare Worker entrypoint still neither passes a transport abortSignal into `handleCmsMedia` nor uses independently authenticated guardian generation. Producer, publisher, CDN and final receiver remain excluded.
