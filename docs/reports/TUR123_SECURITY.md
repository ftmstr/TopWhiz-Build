# TOPWHIZ TUR123 — Transitive SET ROLE reachability and independent rights-admin lease uncertainty (NO-GO)

PostgreSQL 16 role membership security is a **transitive graph**, not only direct INHERIT flags. `broker→relay` and `relay→executor` each with `INHERIT FALSE, SET TRUE` may permit the original broker LOGIN to `SET ROLE executor` despite not inheriting executor privileges. Executor holds SQL EXECUTE on an intentionally elevated test-only SECURITY DEFINER function; the broker's same SQL session can change `current_user` to executor and cancel another HTTP request's active PG16 SQL (57014), even when broker direct `pg_cancel_backend` is 42501. Scoped schema USAGE is explicitly provisioned to executor in the temporary test to avoid the TUR118 setup failure; PUBLIC schema/function EXECUTE remains denied. Operator identity (session_user) still broker.

A distinct restricted LOGIN rights-admin, with ADMIN option on relay only, is the verified grantor of the broker membership edge. Spectator cannot administer it. **ROLLBACK** of revoked edge must restore transitively settable executor; **COMMIT** must cut future role switches for already authenticated broker. The test does NOT claim transport lost-COMMIT ACK; inherited TUR030 independently covers that class. No production SQL roles are modified, no superuser or pg_signal_backend granted to services. Strong future security requires graph-wide SET reachability assessment at each request, independently owned authority, definer owner custody, pool lease generation, accurate SQL cancellation scope and fail-closed revocation/rollback proof.

TUR117 owner-transfer `proacl` grantor rewrite is respected: do not compare ACL text literally. TUR118 INHERIT FALSE/SET TRUE, group EXECUTE and schema USAGE remain inherited regressions.
