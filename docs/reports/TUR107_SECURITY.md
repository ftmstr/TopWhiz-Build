# TOPWHIZ TUR107 — SECURITY DEFINER call privilege vs real request ownership (NO-GO)

Safety hypothesis to disprove: if a SECURITY DEFINER function securely checks `pid`, `backend_start`, `epoch`, and request key against a gate-owned durable lease table then a broker with EXECUTE cannot cancel another request. Counterexample: broker's own SQL login is permitted to execute the function, but is not cryptographically/independently bound to target request. Possession of current tuple is not proof of ownership; the broker can borrow a fresh B tuple and cancel B's active real SQL (57014) through function-owned victim role privilege. Stale ticket is rejected but request-key replay is permitted. Function granted only EXECUTE with restricted search_path, schema ACL and no PUBLIC privilege; broker direct pg_cancel_backend denied 42501; attacker denied function 42501; revoking EXECUTE restores 42501. Real PG16 CI must execute before treating it as observed evidence.

This test creates temporary random LOGIN roles and a NOLOGIN definer in disposable PostgreSQL16, not production SECDEF/CREATE ACL changes. No global pg_signal_backend grants, no service superuser, no license/content/rights changes. Function acts as elevated cancellation authority and is intentionally NOT safe for deployment. Independent external owner/rights-admin IAM, authenticated per-request authorization and connection-pool handoff, PID/back-end start anti-ABA, SQL COMMIT uncertainty, physical Cloudflare/Next signal propagation and true receiver ACK remain unresolved. Inherited TUR074/092/095/096/097/098 SQLSTATE results preserved and TUR099–106 HTTP/2 revocation negative evidence untouched. Issue #22 OPEN and hard release NO-GO.
