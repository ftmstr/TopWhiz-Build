# TUR071 — Security threat-model and fail-closed cancellation

Scope is **opt-in / not deployed**: the live Cloudflare Worker does not hand the original CMS handler a transport-owned AbortSignal. A Node CI HTTP adapter maps physical socket loss to AbortController. The handler's new `readWithAbort` cancels its in-flight R2-like ReadableStream read and denies on abort, while the guardian lookup cooperatively checks the shared signal around SQL reads. Validate no already-queued remote bytes can be recalled; cancellation after the final DB check remains a separate immutable last-byte TOCTOU problem (Issue #22).

Independent disposable PG16 logins, table owners and read-only ACL show only local SQL privileges; no external Neon/Cloudflare IAM, superuser isolation or remote secrets security. Owner/SECURITY DEFINER and CREATE ACL privilege bypass are tracked with TUR056/060 inherited tests. A PG driver query already running may continue despite abort, and a closed socket may not automatically map to abort outside this explicit test adapter. Abort cannot prove CDN cache purge, global zero byte, signed remote receiver ACK, or legal rights clearance. Cancellation errors must not produce 200, must not leak SQL strings or secret credentials. Never advertise a production cancellation fix until the true runtime/connection bridge is implemented and independently audited.
