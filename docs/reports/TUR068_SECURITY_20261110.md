# TUR068 — Transport-level cancellation versus independent guardian / IAM

The disposable PG16 fixture logs in separately as a restricted media reader, media table owner, restricted guardian reader and guardian owner; table ownership and guardian mutation are restricted by actual PostgreSQL GRANT/REVOKE, not application flags. The trusted guardian owner has database power and is **not** independent cloud IAM/credential vault proof. The original CMS handler reads a fictional SHA-256-verified PNG from a deliberately paused streaming source after both SQL authorities approved; physical TCP client abort is observed on the Node HTTP response while the handler is still busy. If the handler continues to consume its source without a request AbortSignal, that is a **negative resource/cancellation result**, not a live R2 incident.

Security boundary: a request can be gone while expensive body verification and database checks continue. A later guardian COMMIT must deny future requests but cannot retroactively cancel all in-flight reads or bytes queued elsewhere. The opposite race, post-final-check 8,273 fictional bytes delivered after acknowledged COMMIT, remains proven in TUR064. TUR018 historic 99,276 fictional bytes/12 schedules and TUR019 cross-isolate remain unresolved.

Inherited TUR060/056 tests cover SECURITY DEFINER and CREATE ACL ownership bypass; those are not re-implemented in this new test. Real external IAM independence, R2/Neon security barrier, cross-region revocation propagation, global CDN purge and last receiver-byte ACK are NOT PROVEN.
