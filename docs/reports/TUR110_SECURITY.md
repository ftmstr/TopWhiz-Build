# TOPWHIZ TUR110 — Default PostgreSQL function PUBLIC EXECUTE privilege and race (NO-GO)

PostgreSQL grants EXECUTE on newly-created functions to PUBLIC by default. If an elevated SECURITY DEFINER cancellation RPC is created/committed before an independent `REVOKE ALL ON FUNCTION ... FROM PUBLIC`, a limited outsider who has schema USAGE can invoke its elevated backend cancellation ability during that interval. Direct outsider SQLSTATE 42501 does NOT prevent indirect function-based cancellation. The experiment independently proves the positive cancellation SQLSTATE 57014 and subsequent outsider revocation 42501 on genuine PostgreSQL16.

Single-transaction CREATE/ALTER OWNER/REVOKE/GRANT before COMMIT ensures the unrestricted function is never visible to outsiders; post-COMMIT PUBLIC EXECUTE is denied. **Critical limitation:** even a correctly scoped transaction is not a request-bound authorization scheme. An explicitly granted broker with only EXECUTE privilege can cancel victim B's current query if SQL function trusts only a caller-supplied PID; legitimate broker membership is not evidence it owns B's request. Separate owner/IAM admin, SECURITY DEFINER search_path, no public schema grants, strongly authenticated caller-to-request SQL ownership, cross-process pooling/PID/epoch/lease and credible cancellation authorization are still required for production.

No service superuser, no global pg_signal_backend, no production SQL mutation; only disposable randomized login roles, synthetic active SQL, distinct guardian owner/reader.
