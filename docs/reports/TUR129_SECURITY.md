# TOPWHIZ TUR129 — SET LOCAL ROLE: safe pooled COMMIT boundary but active in-transaction authorization window

SET LOCAL ROLE limits a role switch to the current PostgreSQL transaction (as documented in PostgreSQL16 SET ROLE and SET). It is not an independently authenticated per-request grant. If a separate rights-admin commits REVOKE while an already running transaction has the executor identity, the SQL effective identity can remain privileged until that transaction finishes. The controlled TEST-ONLY SECURITY DEFINER function can still cancel another live victim's SQL (57014). Unlike TUR125 sticky SET ROLE and TUR126 transactional RESET ROLLBACK, the transaction-local role must disappear after A COMMIT; a pooled B/C client on the same physical backend must see broker and be denied function EXECUTE and new SET ROLE (42501). This is conditional positive isolation evidence for this one mechanism, not proof that application traffic uses SET LOCAL ROLE or has robust cleanup during client disconnect, unknown COMMIT or HTTP2 RST_STREAM.

Test-only roles generated uniquely with no service superuser, CREATEROLE or broad pg_signal_backend; function PUBLIC EXECUTE denied; executor has schema USAGE to prevent TUR118 false negatives. Separate independent restricted LOGIN rights-admin, spectator denial and physical pg.Pool(max:1) A/B/C. Future production requires verified transaction lifecycle under abort/RST, request ownership IAM and transaction cleanup independent from current_user.
