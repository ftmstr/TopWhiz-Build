# TUR072 Security — independent IAM, in-flight SQL and last-byte limits

Adversarial test against ACTUAL disposable PostgreSQL 16 with four distinct non-superuser password LOGINs and independently owned media and guardian tables. Media reader/owner are denied UPDATE on guardian. Real PostgreSQL `pg_stat_activity` demonstrates that an in-flight SQL statement stays active after the client physically disconnects from an HTTP socket and application AbortController fires. Request cancellation is a cooperative **application** signal, NOT proof of backend termination. After SQL finally returns, the opt-in guardian contract denies before independent guardian read and before R2 bucket fetch.

Separate guardian-reader LOGIN must be denied `pg_cancel_backend` against media-reader backend. An intentionally privileged CI-only admin can terminate that query and `57014` is verified. Never grant broad `pg_signal_backend` or superuser to public CMS application or media owner; actual production IAM/Neon authority separation is not validated.
