# TOPWHIZ TUR097 — Cross-login membership is not independent cancellation IAM (NO-GO)

PostgreSQL16 role membership graph is part of authorization. Distinct login names alone do not guarantee independent `pg_cancel_backend` boundaries: an inherited membership of the victim backend owner role can authorize delegated cancellation, even when `pg_signal_backend` was never granted. Equally, `INHERIT FALSE` alone is insufficient when `SET TRUE` permits `SET ROLE` to the victim/current_user. A combination `INHERIT FALSE, SET FALSE` is an important **negative control**, not a complete design proof; false/false grants and strong IAM can be weakened by subsequent owner/role-admin changes. Actual real PostgreSQL16 tests must demonstrate 42501 denied, 57014 cancellation, denial restored after REVOKE, role switch escalation and unrelated outsider denial. A test-only old-epoch ticket is not enforced by SQL.

Preserve no pg_signal_backend, no new service superuser, random disposable role names, independent guardian owner/reader generations and no untrusted PUBLIC grants. Admin fixture can create/revoke ephemeral memberships only for tests. Production rights-admin, schema owner, SECURITY DEFINER/CREATE ACL, pool checkout, app-request lease, backend PID ABA, connection close/session recycle, pg_cancel_backend escalation and cross-process Net/Worker signal need separate hardened approval. No OS PID reuse physical proof, no production per-request SQL cancellation authority.
