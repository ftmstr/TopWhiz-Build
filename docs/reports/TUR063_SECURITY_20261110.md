# TUR063 — independent guardian gate security / NON-PRODUCTION
Separated five password LOGIN roles on disposable PostgreSQL16: media reader, rights revoker, media table owner, guardian owner/writer, guardian read-only verifier. New test-only transport checks **same generation** and guardian approval on every media read; missing anchor / denied anchor / mismatched epoch fail as HTTP404 without bytes. SQL privilege error on guardian SELECT fails as HTTP503 without bytes. The last handler read is still *pre-Response*; residual TOCTOU/queued HTTP byte leakage remains possible and **unproven**.

The media owner can disable its own rights trigger and reapprove locally but cannot rewrite independently owned guardian; real loopback Next HTTP with injected guardian now denies instead of returning PNG. Separate guardReader cannot mutate anchor or media; a media owner SECURITY DEFINER function cannot mutate guardian. Fixture grant/REVOKE demonstrates DB semantics only. A guardian *owner* remains powerful; table owner bypass cannot be solved via SQL guard within same ownership boundary.

No external IAM, no production deployment, no global CDN invalidation, no last-byte receiver ACK. TUR062 unchanged adapter negative test is retained as a distinct regression proving the integration gap persists outside CI. Issue #22 remains OPEN and release NO-GO. A request already past last lookup can still leak bytes after subsequent revocation; do not interpret any local 404 as a remote last-byte guarantee.
