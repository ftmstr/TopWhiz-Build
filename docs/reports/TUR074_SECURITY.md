## Shared-role cancellation cross-request privilege breach — genuine PostgreSQL16
The TUR073 same-role cancel success is NOT request isolation: any authenticated media-reader connection may cancel any other active connection of the SAME login role by backend PID. A new real PG16 adversarial test exercises two independent live reader sessions plus a third same-role canceler, observes both active via `pg_stat_activity`, and proves an unrelated sibling is terminated with SQLSTATE 57014 while the untargeted request finishes. Guardian reader and distinct table owner are denied this operation. Guardian authority is separately owned; guardian-owner COMMIT remains durable, but does not constrain same-role cancellation authority.

Production per-request cancellation requires independently provable session identity, exclusive connection ownership and safe PID lifecycle/pool reuse, none of which are implemented or proven. No global `pg_signal_backend` or superuser grant is recommended. The old invalid-URL 404/400 outcomes are security policy, not a regression: the test was wrong to require 503. Physical Next/Cloudflare transport signal delivery, remote R2/CDN final-byte/ACK, and external IAM remain NOT PROVEN. Issue #22 OPEN, release NO-GO.
