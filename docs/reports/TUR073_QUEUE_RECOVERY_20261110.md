# TUR073 Queue/DLQ, PostgreSQL COMMIT and outbound-byte boundaries

TUR073 makes no changes to immutable original outbox SHA, original route allowlist, queue delivery state, DLQ leases, idempotent retries or transaction recovery. Dedicated workflow carries TUR017/TUR018/TUR019/TUR029 real PG16 tests for canonical receipt SHA, concurrent broker/lease, Queue/DLQ recovery and publication barriers. TUR030 separately exercises ambiguous COMMIT ACK after transport failure; no new claim is made of ambiguous-COMMIT proof.

In the novel Node HTTP test the dedicated non-superuser SQL backend is canceled by a **different authenticated session using the same reader role**. This produces an actual SQLSTATE 57014 on the canceled SELECT while an unrelated sibling SQL backend can finish. Distinct guardian-owner COMMIT sets `approved=false,generation=2`; guardian-reader independently verifies durable revocation; fresh HTTP request denies 404/zero bytes. Cancellation is neither a rollback of prior COMMIT nor proof no bytes have been queued by a remote HTTP proxy/CDN. Historical TUR064/018/069 final-byte negative tests remain independently release-blocking. No external Queue/Neon/R2/CDN/remote receiver ACK, no delivery proof. Issue #22 OPEN, release NO-GO.

A pre-aborted Worker Request can now skip dispatching a new SQL/R2 read, but neither a canceled SQL statement nor canceled HTTP stream proves Queue/DLQ broker ACK, transaction rollback of an already committed mutation, original outbox SHA validity, or receiver final-byte delivery. Existing Queue recovery and COMMIT uncertainty tests remain required.
