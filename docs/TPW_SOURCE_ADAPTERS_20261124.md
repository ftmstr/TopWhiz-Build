# TPW source adapters and retention — 2026-11-24
CI-only; no real official endpoints configured. TPW1 accepts restricted RSS 2.0, default-namespace Atom or strict normalized NEWS_API; TPW3 accepts a normalized DEVICE_API contract, not a universal manufacturer scraper. Operators pin feed HTTPS endpoint, endpoint host, canonical source host, publisher and (device) brand outside the feed. API input is {items:[{url,title,device?}]}; device must contain brand/model/sku/region. Source rights are LINK_ONLY; no raw body or media is persisted. XML parser deliberately rejects unsupported XML (DTD/entities beyond five predefined, nested default namespace, markup title, ambiguous links), and may reject legitimate feeds until adapted. No source ownership, real provider API, or publication rights have been verified. News identity is hash of exact canonical URL; device identity is hash of brand/SKU/region; URL aliases and device revision history remain open. Private pilot cannot use the old arbitrary JSON feed mode.
Fresh official re-observation can move only older PENDING records with same id/kind/source URL/publisher/rights, never PROCESSING or terminal records within the existing TTL. It is not a guarantee against replay after tombstone expiry or a distributed write fence. No automatic carry-forward without new feed observation. Operational run retention: delete terminal rows strictly older than 30 days with no referenced stage row; active runs are not pruned. Application cleanup is not secure physical erasure; database backup retention requires separate review. Issue #22 HARD NO-GO; no deployment, true content, or new automation.
